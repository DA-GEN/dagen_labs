# Глосарій предметної області - Dungeon Game

Цей глосарій фіксує терміни предметної області (ігрової логіки) та основні
архітектурні поняття, що використовуються в коді й документації проєкту.
Терміни наведено українською мовою; у дужках вказано відповідний
ідентифікатор/клас у вихідному коді (англійською), якщо такий є.

## Ігрові сутності

| Термін | Визначення |
|---|---|
| **Персонаж** (`Character`) | Абстрактна базова сутність, що має ім'я, очки здоров'я (HP), силу атаки та захист; вміє атакувати, отримувати шкоду, лікуватися й перевіряти, чи живий. Спільний предок гравця та ворогів. |
| **Гравець** (`Player`) | Персонаж, яким керує користувач; має інвентар предметів і належить до одного з ігрових класів (Воїн/Маг/Лучник). |
| **Ворог** (`Enemy`) | Персонаж, керований грою (НПС), що населяє кімнати підземелля та протидіє гравцеві в бою. |
| **Ігровий клас** | Спеціалізація гравця, що визначає його унікальну поведінку в бою: **Воїн** (`Warrior`), **Маг** (`Mage`), **Лучник** (`Archer`). |
| **Воїн** (`Warrior`) | Ігровий клас, що спирається на фізичну силу атаки та підвищений захист. |
| **Маг** (`Mage`) | Ігровий клас, що завдає магічної шкоди (`DamageType::Magical`), яка по-іншому опрацьовується захистом цілі. |
| **Лучник** (`Archer`) | Ігровий клас зі здатністю завдавати критичного удару з певним шансом (`crit_chance_`), що визначається генератором випадкових чисел. |
| **Гоблін** (`Goblin`), **Орк** (`Orc`), **Привид** (`Wraith`) | Конкретні типи ворогів із власними характеристиками. Привид має фізичний резист (`physical_resistance_`) - применшує отриману фізичну шкоду, але вразливий до магічної. |
| **Тип шкоди** (`DamageType`) | Перелік (`Physical`/`Magical`), що визначає, як саме застосовується захист цілі при отриманні шкоди (`apply_defense`). |

## Предмети та інвентар

| Термін | Визначення |
|---|---|
| **Предмет** (`Item`) | Абстрактна сутність, яку можна використати (`use`); має назву й опис. |
| **Зброя** (`Weapon`) | Предмет, що підвищує силу атаки персонажа. |
| **Броня** (`Armor`) | Предмет, що підвищує захист персонажа. |
| **Зілля** (`Potion`) | Витратний предмет, що відновлює здоров'я персонажа. |
| **Інвентар** | Колекція предметів, підібраних гравцем під час проходження підземелля. |

## Підземелля та навігація

| Термін | Визначення |
|---|---|
| **Підземелля / Карта** (`GameMap`) | Сукупність кімнат і переходів між ними; відповідає за генерацію світу, розміщення ворогів і предметів. |
| **Кімната / Вузол карти** (`MapNode`) | Окрема локація підземелля з описом, опціональним ворогом і опціональним предметом. |
| **Граф** (`Graph<T>`) | Узагальнена структура даних "список суміжності", що моделює зв'язки між кімнатами та підтримує пошук шляху (BFS/DFS). |
| **Фінальна кімната** | Кімната-вихід із підземелля; досягнення її є однією з умов перемоги. |
| **Сусідні кімнати / Виходи** | Кімнати, безпосередньо з'єднані з поточною; гравець переходить між ними під час дослідження. |

## Ігровий процес

| Термін | Визначення |
|---|---|
| **Раунд бою** | Обмін ударами між гравцем і ворогом у поточній кімнаті: атака гравця → перевірка смерті ворога → контратака ворога → перевірка смерті гравця. |
| **Перемога** | Умова завершення гри на користь гравця: знищення всіх ворогів підземелля АБО досягнення фінальної кімнати. |
| **Поразка** | Умова завершення гри не на користь гравця: очки здоров'я гравця досягають нуля. |
| **Журнал подій** | Послідовність текстових повідомлень про дії та події гри, що показуються користувачеві. |
| **Характеристики** (статистика) | Поточні чисельні показники персонажа (HP/максимальне HP, сила атаки, захист), що відображаються в інтерфейсі. |

## Архітектурні поняття (введені під час рефакторингу)

| Термін | Визначення |
|---|---|
| **Ігровий рушій** (`GameEngine`) | Клас, що інкапсулює всю ігрову логіку у вигляді, незалежному від Qt; відповідає за стан гри та обробку дій гравця. |
| **Спостерігач гри** (`IGameObserver`) | Інтерфейс, через який `GameEngine` сповіщає підписника про ігрові події (повідомлення в журнал, зміну статистики, оновлення кімнати, початок/завершення гри), не знаючи нічого про конкретний UI. |
| **Контролер гри** (`GameController`) | Тонкий Qt-адаптер, що реалізує `IGameObserver`, отримує події від `GameEngine` і транслює їх у Qt-сигнали для `MainWindow`. |
| **Постачальник випадковості** (`IRandomProvider` / `RandomProvider`) | Абстракція над джерелом випадкових чисел, що впроваджується (Dependency Injection) в усі компоненти, яким потрібна випадковість (генерація підземелля, фабрики, критичний удар Лучника), забезпечуючи детермінованість у тестах. |
| **Фабрика ворогів / предметів** (`IEnemyFactory`/`EnemyFactory`, `IItemFactory`/`ItemFactory`) | Абстракції, що інкапсулюють створення конкретних типів ворогів і предметів, звільняючи `GameMap` від знання про конкретні класи (Goblin/Orc/Wraith/Weapon/Armor/Potion). |
| **Шаблонний метод** (`apply_defense`) | Точка розширення в `Character::take_damage`, що дозволяє підкласам (наприклад, `Wraith`) по-своєму опрацьовувати захист залежно від типу шкоди, не дублюючи весь алгоритм отримання шкоди. |

## Скорочення та позначення

| Скорочення | Розшифрування |
|---|---|
| HP | Health Points - очки здоров'я персонажа |
| OCP | Open/Closed Principle - принцип відкритості/закритості (SOLID) |
| SRP | Single Responsibility Principle - принцип єдиної відповідальності (SOLID) |
| DIP | Dependency Inversion Principle - принцип інверсії залежностей (SOLID) |
| DRY | Don't Repeat Yourself - принцип "не повторюйся" |
| DI | Dependency Injection - впровадження залежностей |
