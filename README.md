# Dungeon Game

Покрокова рольова гра з процедурно згенерованим підземеллям. Гравець
обирає ігровий клас (Воїн, Маг, Лучник), досліджує кімнати, б'ється з
ворогами (Гоблін, Орк, Привид), підбирає предмети (зброю, броню,
зілля) і прагне або зачистити підземелля від ворогів, або дістатися
фінальної кімнати.

## Структура репозиторію

- [`core/`](core/) - Qt-незалежна бібліотека з усією ігровою логікою
  (`GameEngine`, доменні моделі, фабрики, генератор випадковості). Не
  має жодної залежності від Qt і збирається/тестується окремо.
- [`ui/`](ui/) - тонкий Qt-адаптер (`GameController`, `MainWindow`),
  що підписується на події `core` через інтерфейс `IGameObserver` і
  показує стан гри у графічному інтерфейсі.
- [`tests/`](tests/) - юніт-тести `core` на основі GoogleTest.
- [`UML_As_Is/`](UML_As_Is/), [`UML_To_Be/`](UML_To_Be/) - діаграми UML
  "до" і "після" архітектурного рефакторингу (джерела `.puml` і
  відрендерені `.png`): прецедентів, класів, послідовності,
  компонентів, активностей, станів, об'єктна, комунікації та
  розгортання.
- [`UML_Extra/`](UML_Extra/) - додаткові завдання лабораторної:
  концептуальна модель архітектури месенджера на кшталт Telegram
  (разом із пропозицією й моделюванням нової фічі "Спільні завдання
  в чаті") та діаграма активностей за сюжетом фільму "Назад у
  майбутнє".
- [`Glossary.md`](Glossary.md) - глосарій термінів предметної області.
- [`Report_Analysis.md`](Report_Analysis.md) - звіт з аналізу
  архітектури, опис застосованих патернів проєктування (SOLID, Observer,
  Factory Method, Template Method, Dependency Injection, Adapter) і
  порівняння метрик коду до й після рефакторингу.

## Складання та запуск тестів

```sh
cmake -B build -S . -DDUNGEON_BUILD_TESTS=ON
cmake --build build -j
ctest --test-dir build
```

Бібліотека `core` - header-only (`INTERFACE`-ціль CMake) і не вимагає
встановленого Qt SDK для складання чи тестування.

## Складання Qt-застосунку

```sh
qmake dungeonqt.pro && make
```
